# 精简任务验收证据留存策略

## 目标

在 Trellis 发布规则中明确临时材料从产生、诊断、交接到筛选和清理的完整流程，防止原始过程默认堆进仓库，同时保持失败记录诚实。缩小改动面，不增加工具兜底。

## 背景

Task Viewer 验收曾生成397个中间文件、约2.5MB，用户清理后仅留约2KB最终摘要。既有workflow已要求证据按需，但没有明确“诊断期间保留”与“永久入仓”的区别；主会话宽泛委派又放大了落盘范围。

现有implement/check角色已经默认返回结果、持久化需授权，本任务不重复修改它们。当前项目 `.trellis` 规则只读；本任务调整发布源，项目应用通过 Trellis apply 完成。

## 需求

- R1（产生）：执行前用系统临时目录创建本次仓库外运行目录（如 mktemp -d）。原始stdout/stderr、完整事件流、批量终端text/ANSI/raw、临时driver/启动脚本、调试指纹及重复阶段报告默认写这里。不新增仓库内.tmp或存储配置。
- R2（诊断）：失败后保留诊断需要的原始材料，先核验原因并复测，不能在主会话核验前清理。不得用最终成功覆盖失败事实。
- R3（交接）：子代理返回简明结论、未解决问题及主会话需要读取的临时路径；主会话继续调查可沿用这些材料，不为了方便读取/交接复制到仓库。无需每角色/每阶段独立持久化报告。
- R4（精选）：主会话核对后，把最终命令、环境、退出码、结果、失败原因和复测关系及未运行限制优先写implement.md（轻量任务可用PRD）；必要报告可选。只有未解决问题或确有长期复现价值的最小材料，经主会话选择、说明用途并脱敏后进入evidence。正式记录不能仅依赖即将删除的临时日志链接。
- R5（清理）：在现有执行/收尾授权范围内，确认材料已核验、没有活动进程仍在使用后，清理本次创建且确认归属的临时目录。不得广泛清理系统临时目录、其他会话文件或历史task；无法确认权限/归属、未解决诊断或清理失败时保留并报告原因和位置，不宣称已清理。
- R6（提交前审查）：任何可能提交任务目录的提交、journal或archive动作之前，主会话检查tracked/untracked新增材料，确认最小保留集合，合并重复总结。不把“属于本task”当作“应入仓”。
- R7（范围）：只改一个发布workflow模板和两个技能的局部规则及必要测试/hash。项目 `.trellis` 工作流/spec/config/runtime、`.pi/agents`、安装资源不直接改；同步通过Trellis apply，本任务不对当前项目执行apply。

## 精确修改范围

| 文件 | 改动 |
| --- | --- |
| `resources/templates/workflow.md` | 定义仓库外临时目录及材料类型、诊断期保留、临时路径交接、主会话精选和失败诚实性；委派与任务目录提交前遵循此契约。 |
| `skills/trellis-check/SKILL.md` | 材料检查先判断是否需要入仓；核对失败/复测、临时与正式材料、最终记录的自足性，不强制报告。 |
| `skills/trellis-finish-work/SKILL.md` | 任何journal/archive前检查最小保留集合；核验活动进程/归属/授权后清理自有临时目录，准确报告保留与残余。 |
| `tests/workflow-policy.test.mjs` | 增加一组跨上述三文件的契约检查，保留既有授权、phase提取、commit与source边界测试。 |
| `resources/template-baseline.json`、`resources/skill-baseline.json` | 仅更新上述三个发布文件输出hash，来源hash/版本/许可不变。 |

三个规则文件不是三份复制的长流程：workflow是通用规则owner，check和finish仅写各自检查责任与简短引用。

## 验收标准

- A1→R1：发布规则明确原始运行材料默认仓库外系统临时目录，不默认task/evidence或仓库.tmp。
- A2→R2/R3：诊断前不删原始材料、交接临时路径且不复制入仓；报告非必需，失败与复测事实不丢失。
- A3→R4：主会话核验后形成自足最终记录；长期附件仅按价值精选脱敏，不能引用已删除临时路径代替结论。
- A4→R5/R6：提交/journal/archive前含tracked/untracked材料审查；清理仅自有且不再使用的目录，异常/未解决情况明确报告，原授权边界不放宽。
- A5→R7：实际规则改动严格限三文件，配套仅一测试文件和两baseline；项目运行规则、角色、runtime/派发代码均不变。
- A6：合同测试和现有资源完整性/phase解析/生命周期授权回归通过；静态规则检查不冒充所有Agent必然遵守。
