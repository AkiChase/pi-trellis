# 任务浏览面板列对齐与溢出省略

## 目标

让 `/trellis-task-viewer` 的任务列表能够纵向扫描：状态、任务目录名、标题起点稳定；超长内容有明确省略，不越过终端边界或挤掉其他列。

## 授权与范围

- 用户已批准按本方案实施（“开始做吧”）；包含验证后的单阶段本地提交。
- 仅修改本仓库 Trellis Task Browser 列表展示，不涉及邻仓 Task Panel、其他插件面板、任务存储或生命周期。
- 不改变键盘交互、排序、当前任务树置顶、刷新保持选择、详情和文档浏览。
- 不安装、同步、重载、推送、归档或记录会话；保留所有并行变更。

## 已确认的代码依据

- `lib/task-browser/component.ts:213-227` 的 `listLine()` 直接拼接当前标记、可变宽状态及 `row.prefix + taskLabel()`；仅剩余文本和整行使用 `truncateToWidth(..., "…")`，未分列。
- `lib/task-browser/reader.ts:258-263` 的 `taskLabel()` 将目录名和标题拼成 `name · title`，同名时不重复；详情也使用它，列表分列不应改变详情语义。
- `lib/task-browser/reader.ts:227-234` 提供树前缀，应保留父子层级。
- `tests/task-browser-ui.test.mjs` 已覆盖终端宽度、当前标记、树置顶、选择保持和长目录名详情可达；现有整行拼接断言需按新展示更新，不削弱详情可达性。

## 展示要求

### R1 列对齐

- 列表按「当前标记 / 状态 / 任务目录名 / 标题」布局；保留状态原文和颜色。
- 标记列固定 2 个终端单元；状态列统一宽度，至少容纳 `[in_progress]`，未知长状态不得无限撑宽。
- 目录名列包含现有树前缀，父子缩进仍可辨认；标题统一起点。
- 列宽基于完整任务列表和当前窗口宽度计算，不随可见行或选择位置变化；刷新或窗口尺寸变化可以重新计算。
- 相同目录名和标题不重复显示。

### R2 按列省略与响应式布局

- 目录名列按实际内容计算宽度但设上限，标题占剩余宽度；目录名过长仅在自己的列内用 `…` 省略。
- 常规宽度给标题保留可读空间，不能让单个长目录名挤掉所有标题。
- 标题过长在自己的列内用 `…` 省略；列表保持单行，不换行。
- 窄窗口切换紧凑展示，先保证当前标记、状态和目录名可辨认，空间不足可隐藏标题，不保留无意义空列或分隔符。
- 极窄窗口也不越界；无法完整显示状态时安全截断，不承诺几列均可见。
- 使用实际终端显示宽度辅助函数，兼容中文、emoji、组合字符与 ANSI 颜色；先清理不可信控制字符再着色。
- 精确列宽上限和切换阈值在实施时通过实际宽度用例确定，遵循上述优先级；不增加用户配置。

### R3 保持现有行为

- 保留选中行背景填充、当前标记、状态颜色、层级、滚动和刷新选择。
- 进入详情后可查看完整目录名与标题，省略不改写源数据。
- 诊断行仍清晰可见并按整行安全截断。
