# 后续子任务自主执行授权

用户于当前回合明确要求：“你后续一步步完成所有的子任务吧，我就不一一审批了，都交由你来完成”。

## 已授权

- 在已确认父任务范围内，按 runtime → init → migration → 父任务集成验收顺序自主推进。
- 主会话负责细化各子任务设计/计划、规格加载、实施、测试与独立检查；不再逐项要求用户重复批准。
- skills 随包加载；不生成初始前后端 spec，不做多 package 检测/配置，不含 channel/mem 和一般旧项目迁移。
- 初始化英文 UI 和自定义/历史用户名，行为按已审计上游 identity/workspace/onboarding 契约。
- 定向迁移本仓库受管资源，保留项目数据/历史/用户定制；内容和引用迁移完成后删除仅本仓库 `.agents/`。
- 仍须执行规划和质量门禁；授权不是跳过规格、测试、独立检查或依赖顺序。

## 仍须停下的情况

新功能/修复超出已确认范围、需覆盖用户定制、出现不能安全保留的并行冲突、必要的高风险不可逆操作，主会话先报告再决定，不推断扩大授权。

根据用户后续明确要求，已验收子任务应及时提交；未完成内容仅在确认完整、可验证的提交边界后做阶段性提交。不自动执行 push、真实插件 install 或全局环境变更。父任务完成需报告实际验证和残留限制，不用内部子任务完成替代整体验收。

## 文档处理

子任务及父任务旧文档中的逐项“待下一轮用户确认”是授权前门禁；在上述已确认范围内已由本次统一授权满足。仍须补齐设计/计划/context 并检查一致性后才能进入各自实施阶段。
