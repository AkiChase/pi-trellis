# Task Viewer 滚动条与鼠标滚动

## 目标

为 `/trellis-task-viewer` 列表和文档正文增加常驻原生滚动条及 Fullscreen 鼠标滚轮支持，让长内容连续可浏览；保留只读职责、固定区域和 Regular 键盘回退。

## 背景与技术事实

- `lib/task-browser/component.ts` 目前用 `listOffset`、各详情页 `offsets` 和数组截取管理视口，仅有键盘输入。每次 render 会让列表选中项可见，直接加滚轮会被旧选择拉回。
- `lib/task-browser/command.ts` 打开全窗口 overlay，不改变 Pi 的运行模式。
- 已安装 Pi 1.2 的公开 API 包括 ScrollView、Stack 布局、标准化鼠标事件。ScrollView.render 本身输出完整子内容；实际裁剪和滚动条需要原生布局树识别 ScrollView，不能只包裹现有手动截取输出。Fullscreen 路由鼠标，Regular 将鼠标交给终端。
- 当前没有独立页码切换界面；用户指定移除手动分页及 PageUp/PageDown 快捷键，直接使用原生 ScrollView，不自制滚动条。

## 需求与验收

| ID | 需求 | 可观察验收 |
| --- | --- | --- |
| R1 / A1 | 列表和详情正文使用常驻原生滚动条；标题、页签、底栏固定。 | 原生布局分配后的实际视口占满 overlay，滚动时固定区域不移动、底层内容不泄露，滚动条反映当前位置。 |
| R2 / A2 | Fullscreen 滚轮连续滚动，正文上下边界不穿透底层主对话。 | 列表/诊断/四个详情页可正反滚动到末尾，到边界继续滚动不改变主对话位置。 |
| R3 / A3 | 滚轮只改变视口；键盘选择才确保选中项可见。 | 滚轮离开旧选中项后渲染不拉回，方向键仍正确移动选择并显示，Enter 打开所选任务。 |
| R4 / A4 | 列表及四个详情页位置独立保存，刷新和缩放合理保留或 clamp。 | 切换页签、返回列表保留位置；删除/刷新/当前树重排保留有效身份，不误打开其他任务、不越界。 |
| R5 / A5 | Regular 保留键盘操作和可视滚动条，不强行捕获鼠标或切换运行模式。全窗口浏览效果为目标，overlay 不是强制实现方式。 | 两种宿主布局均可浏览和正常关闭，恢复编辑器文本与焦点；Regular 不增加鼠标捕获副作用。 |
| R6 / A6 | 原生 ScrollView 为唯一视口权威，去掉旧 slice 分页与重复偏移管理。 | 通过实际宿主原生布局和滚轮路由测试，不以只调用 render 或自制滚动条代替验收；原生能力阻碍须报告，不能擅自回退自制方案。 |
| R7 / A7 | 移除 PageUp/PageDown，保留方向键、Enter、左右页签、Esc 和 r。 | 翻页键不改变选择/滚动位置；界面及用户文档无翻页键提示，其他键位保持可用。 |
| R8 / A8 | 仅新增滚动支持，不额外开发任务行点击选择、滚动条点击/拖动。 | 不新增这些自定义交互；原生默认能力不刻意禁用。 |
| R9 / A9 | 保留宽度/主题/只读与错误回退契约。 | 滚动条预留列后中文/emoji/ANSI 与极窄布局不越界，主题变化更新；大文档与 Markdown 失败原文可达末尾；操作不改变文件、session pointers、Git index，不调用模型/生命周期。 |

## 验证层次与限制

- 自动化：实际宿主布局与 mounted overlay 测试，加 focused UI/reader/display 及全量测试；组件测试不是物理鼠标验收。
- 真实终端：需要单独明确授权的隔离 Pi Fullscreen/Regular 测试；未授权/未运行记为 NOT_RUN，不能声称真实鼠标验收通过。输入注入不等同物理滚轮端到端验证。
- 用户说明更新 `docs/task-viewer.md`；开发/测试规范不放 docs。

## 范围外

任务编辑、切换当前任务、归档搜索、额外自定义点击/拖动交互、Pi 本体修改、强制切换个人 Fullscreen、安装/同步/个人重载、推送、历史任务整理、未授权真实终端或在线模型访问。

## 已解决的接口决策

接口阻碍已由用户授权解决：采用隔离内部 renderLayoutFrame 适配，保留全窗口 overlay、原生 ScrollView 和公开 handleMouse wheel bridge，不替换 Pi 主布局。内部 API 的升级风险已接受；能力失效时明确诊断，不自制降级。设计核实证据与最终方案见 design.md。
