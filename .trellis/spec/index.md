# Project Guidelines

No project-type rules are generated by initialization. After approval, use
`/skill:trellis-spec-bootstrap` to build guidelines from real project evidence.
Start with [thinking guides](guides/index.md), then discover relevant layer indexes.
Keep private project conventions here, not in the package skills. Read
[Documentation Maintenance](documentation.md) for content placement, language,
reference updates and historical evidence requirements.

Small-feature usage and implementation documents belong in root `docs/`, not
in `.trellis/spec/`. Keep only shared coding guidelines, architecture and
cross-module engineering boundaries here. See the [documentation index](../../docs/index.md).
