# Development Guidelines

## Pre-Development Checklist

Read the approved PRD/design/implementation plan, this document, [testing guidelines](../testing/index.md) and [shared guides](../guides/index.md). Read complete relevant owners, callers and tests: search excerpts locate evidence but do not establish a contract. Before nontrivial edits state the smallest behavior gap, expected files/side effects and exclusions. Read-only findings, task status and CLI confirmation flags do not grant implementation approval.

## Source Ownership and Coding

This is one ESM Pi package, not a Web service or monorepo. Use explicit `.ts` imports, type-only coding-agent API imports, Node built-ins and the real host TUI width helpers. Keep presentation in `extensions/trellis.ts` / task-browser components, shared task loading in `lib/task-context.ts`, initialization publication in `lib/initialization/`, provider/occupancy integration in `lib/{subagent-rpc,executions,source-executions}.ts`, and native management/material policy in `runtime/pi_trellis_worktree/`. Test-only `__internals` are not public APIs.

`runtime/` is package source; `.trellis/scripts/` is project deployment. Do not repair product behavior by editing a deployed copy, duplicating Python management policy in TS, or copying uncommitted source into a target baseline. The host consumes authoritative Python query facts; path-only dispatch rendering has its own owner. Reuse validators only when semantics match: cosmetic UI degradation and safety-critical preparation failure are intentionally different.

Use local runtime validators for external JSON, not TypeScript assertions as proof. Preserve existing guarded state transitions rather than introducing an unrelated universal decoder/reducer. Subprocesses use argv arrays. Git subprocess environments remove inherited `GIT_*` redirection and set `GIT_OPTIONAL_LOCKS=0` without modifying the parent environment. Preserve Unicode/terminal-column semantics and sanitize untrusted controls before styling. Avoid variadic expansion of unbounded rendered arrays.

## Identity, Context and Materials

- Resolve the project from each event's current cwd; inspect `.trellis` before stopping at the nearest `.git` file/directory, and never skip an unsafe marker to activate an ancestor. Ordinary uninitialized startup performs no Python probe or project writes. Only init registers unconditionally; supported session startup registers viewer commands and dispatch tools separately. Rebuild registrations on reload rather than mutating host-private registries. Conditional skills use public Pi resource resolution and a read-only, scope-aware settings view; explicit filters, trust and other packages retain host semantics. Invalidation clears both UI surfaces and blocks runtime execution; a valid project without a current task still displays its count. Cache keys include project/session identity. Pass explicit context keys to subprocesses/bash, never publish per-session identity into shared `process.env`. A valid caller pin intentionally shares identity; derived children still bind independent keys before failure can expose a parent pointer.
- Accept CLI task results only on successful exit, exact `session:<key>` provenance and no stale/error. Invalid pointers/records retain task_error, never authorize materials, hooks, journal paths or a no-task success. Child binding runs no start/hooks; clearing its pointer must not resurrect it from remembered dispatch headers.
- Task references are lexical descendants of `.trellis/tasks/` and realpath descendants of the resolved store. Only the explicit top-level source task-store route permits external material; target task stores, runtime/session stores and arbitrary references do not inherit that exception. Canonicalize existing ancestors without creating paths; dangling symlinks are not free destinations. Use bounded regular-file reads, UTF-8/NUL validation and explicit diagnostics; retain source/test-defined byte, traversal, expansion and diagnostic limits.
- Native source material validation selects common artifacts plus only the dispatched implement/check role JSONL; research has no implement/check manifest requirement. Every dispatch rereads source bytes, including same-mtime changes, deduplicates canonical files and bounds directory expansion. Broken/empty references fail before spawn with source path/manifest-line diagnostics; another role's invalid references do not block this role.
- `assembleDispatchPrompt()` owns the exact four-line authority header and delimiters: task, independent context, role, native source-authority JSON, then a blank line. Strip caller-owned headers/legacy markers; never emit material bodies or a complete-injection/read claim. Parsing is syntax, not authorization: child consumers compare native source/binding identity and authority paths. Missing/invalid headers or source material have no local-current/target-copy fallback. Roles fully paginate absolute source artifacts, workflow, selected manifest/references; product reads/writes stay at executionRoot. Paths/fingerprints are not actual-read proof.
- Stable system sections contain stable workflow/overview only; volatile task state is a deduplicated message and role material is read directly from source paths, not embedded in dispatch prompts. Cache invalidation must follow root/session/role and task-changing events. Do not claim every cache is cleared or dispatch materials are cached permanently.

## Files, Publication and Resource Provenance

Installation registers the Pi package; explicit confirmed initialization/resource actions publish project resources. Startup never deploys roles, upgrades runtime, selects tasks or installs dependencies. Existing workflow/config/spec/history are user-owned. Safe updates preserve customizations and reject executable/role conflicts; explicitly confirmed manifest-less adoption and template replacement are distinct destructive actions, not safe updates.

The schema-2 project manifest separates exact executable resources from editable template provenance. Preserved-project fingerprints/revisions are diagnostics, not arbitrary read/write/recovery authorization. Initialization recovery reconstructs canonical package/skeleton outputs and verifies original ownership, not merely a planHash. Guard paths, source/output bytes and mode again under lock and before publication; publish the manifest last. Atomic replacement is per-file, not a multi-file transaction or OS sandbox. Failures preserve published files and history; inspect existing locks rather than deleting them as stale. Template replacement preserves its required backups.

`scripts/install.sh` stays Pi-only; historical patch/native-only deployment utilities are not full initialization or manifest bypasses. Bundled skills/templates/roles are package resources; project rules do not belong there. Preserve phase/state markers, role recursion guards, explicit direct-execution empty-manifest handling and independent implementation/review choice when those resources are intentionally changed.

Bundled `agents/trellis-{implement,check,research}.md` are directly maintained authoritative package source, not regenerated outputs. Preserve their historical Claude/Trellis **0.6.17** attribution, modification notices and AGPL license. `resources/agent-baseline.json` retains historical source hashes/platform/version; update only affected adapted hashes to match reviewed current files. Historical hashes do not prove new generation or authenticate arbitrary input. Project `.pi/agents/` is a deployed/custom resource, not the package editing location; preserve custom bytes and existing explicit initialization/resource-publication contracts.

Keep original MIT integration/native code distinct from **AGPL-3.0-only** Trellis-derived runtime **0.6.16** and adapted roles **0.6.17**. Preserve attribution/modification notices, full original/output hashes and license metadata; the package is `(MIT AND AGPL-3.0-only)`, not wholly MIT/upstream-free. A source hash without the source is not independent integrity proof. See the [runtime baseline](../../../resources/runtime-baseline.json), [role baseline](../../../resources/agent-baseline.json) and [README license notice](../../../README.md#license).

## Worktree, Dispatch and Failure Preservation

- One native management owner implements preview/confirmed transitions; status and previews are no-write. Confirmation recomputes under the exclusive source lock, not from a persisted reservation. Default HEAD may change; bindings pin a full commit and canonical source/target/common-Git identity. Config changes affect new creates, not existing absolute bindings.
- Validate authoritative source records, Git registration/branch and local runtime paths; a target marker is only a hint. Reject overlapping/unsafe destinations, tracked/nonignored runtime paths and incompatible identity. Create/adopt never copies source code, installs, starts tasks or launches agents. Failure retains created directories/branches and error records.
- Main source is the only task/spec/workflow/JSONL authority. Preparation validates source role material and target execution configuration, writing ignored runtime state only: no task/spec copy, target task.json edits, task start/hooks or target pointer. Target Git-checkout `.trellis` remains untouched and is never a material fallback. Source uncommitted requirements may be read; no clean-source/target-baseline equality gate or symlink/sparse-index masking.
- Bindings accept strict version 2 only; old/unknown formats fail explicitly without migration, conversion or automatic deletion. No refresh/collect, dual-copy descriptor, accepted graph or material ancestry. Main verifies obsolete source references, repairs them within existing maintenance authorization, then requeries/redispatches. Recoverability is not write authorization; conflicts or scope changes must be surfaced.
- Child source material access is read-only by default. Main owns task/spec integration and lifecycle; implementation/check returns evidence by default, with explicitly authorized source task evidence/ writes only. Research writes only explicitly authorized source task research/*.md. Task identity, header paths and tools are not arbitrary source write permission or an OS sandbox.
- Unbound tasks may use shared-source execution; different tasks may overlap but the same active/unknown task cannot. Bound tasks require existing prepared managed targets and never fall back to source or temporary isolation. Actual host cwd and persistent adapter/compatible role configuration are checked; a prompt cwd or parent-only `-e` is insufficient.
- Reserve starting before public spawn RPC, requery/recheck authoritative identity/readiness/fingerprints under lock, and render source authority paths (no bodies) for the target execution cwd. Return real provider IDs. Early terminal events reconcile with spawn replies; uncertain spawn/shutdown retains unknown. Stop requests cancellation but does not release occupancy before terminal evidence. Conditional source terminal publication rechecks request/state under the same lock and defers contention; exit is not a durable-flush guarantee.
- Ordinary Trellis subagent_run interception cannot cover third-party RPC/workflow launches; tools/roles/worktrees are not an OS sandbox. Invalid neighboring discovery can diagnose independently, but direct record reads remain strict. No automatic phase advancement, install, commit, merge or provider retry.
- Completed check snapshots are freshness evidence, not acceptance; both starting requirement revision and final checkout snapshot must remain current. Exclusions and large-file metadata fallback are not exhaustive change detection. Recovery requires proof of owner death, rechecks under lock and resets preparation, not arbitrary identity/material repair. Nonpositive/group PIDs, permission errors and unsupported probes cannot prove death.
- Removal refuses active/unknown execution, actual/supplied cwd, dirty targets and nonancestor integration references. Report ignored-file risks; ordinary Git remove only, no force/branch deletion. Remove only this binding's runtime binding/execution records after success. Preserve outputs through separately approved product integration first.

Evidence: `tests/{worktree,worktree-cli,preparation,dispatch,source-executions}.test.mjs`, `tests/python/test_worktree.py`. Exact user commands belong in [worktree usage](../../../docs/worktree-execution.md), not another lifecycle spec.

## Task, Journal and Developer Safety

Fixed task/context/developer/journal code accepts only explicit valid keys, bounded valid task records and exact store paths; no sole-session/platform fallback. `task.py active` only binds the caller, with no status/branch/hooks/context-readiness effects; multiple sessions may bind the same task. Idempotent activation preserves pointer bytes, invalid caller pointers remain diagnostics, and no foreign-session cleanup or new binding lock is involved. Deactivation clears only the calling pointer after successful unlink, runs hooks only for a valid task and does not finish/archive it. Bad/final symlink pointers must not authorize target reads or hooks. Archive rejects unsafe destinations before status/child/pointer changes. Journal/archive commit scopes are exact validated paths and preserve unrelated staged work; external stores are not mapped to a local same-name directory.

Developer names are safe nonempty single segments with source-defined limits; preserve legitimate Unicode/space names and historical journals. Reject dot/traversal/separators/control/format/surrogate names and symlink identity/workspace routes. Existing different identity is a conflict, not a silent switch. Preserve no-bytecode/no-global-Trellis behavior. Trusted hooks may run shell: validation is not a hook sandbox.

## Documentation Maintenance and Review

Specs are **English**, docs/ and task artifacts **Chinese**; README retains its language. Identifiers, commands, hashes and quoted upstream text are not translated. `docs/` is for users: feature behavior, commands, configuration and visible limitations. Keep package provenance in resource manifests and necessary license notices in README/license/source files, not standalone user pages. All development/testing methods belong in specs; historical designs/results belong in tasks. A small feature does not require a new spec file.

Classify before moving: retain effective reusable constraints, consolidate current user explanations and preserve archived evidence. Do not mechanically concatenate internal schemas/algorithms into a giant manual. Keep root navigation short; layer indexes contain real guidance; retain skill-required guides paths without repeated prose. Update current Markdown/JSONL paths and anchors, not archived assertions en masse. Never regenerate/install/deploy merely to repair a document link.

Review actual staged/unstaged/untracked and supplied-base committed changes, caller behavior and negative-case preservation. Self-review is not independent review. Keep approval, verified execution, check freshness, acceptance and lifecycle authorization distinct. Record exact final checks and limits under [testing guidelines](../testing/index.md).
