# Development Guidelines

## Pre-Development Checklist

Read the approved PRD/design/implementation plan, this document, [testing guidelines](../testing/index.md) and [shared guides](../guides/index.md). Read complete relevant owners, callers and tests: search excerpts locate evidence but do not establish a contract. Before nontrivial edits state the smallest behavior gap, expected files/side effects and exclusions. Read-only findings, task status and CLI confirmation flags do not grant implementation approval.

## Source Ownership and Coding

This is one ESM Pi package, not a Web service or monorepo. Use explicit `.ts` imports, type-only coding-agent API imports, Node built-ins and the real host TUI width helpers. Keep presentation in `extensions/trellis.ts` / task-browser components, shared task loading in `lib/task-context.ts`, initialization publication in `lib/initialization/`, provider/occupancy integration in `lib/{subagent-rpc,executions,source-executions}.ts`, and native management/material policy in `runtime/pi_trellis_worktree/`. Test-only `__internals` are not public APIs.

`runtime/` is package source; `.trellis/scripts/` is project deployment. Do not repair product behavior by editing a deployed copy, duplicating Python management policy in TS, or copying uncommitted source into a target baseline. The host consumes authoritative Python query facts; bounded prompt rendering has its own owner. Reuse validators only when semantics match: cosmetic UI degradation and safety-critical preparation failure are intentionally different.

Use local runtime validators for external JSON, not TypeScript assertions as proof. Preserve existing guarded state transitions rather than introducing an unrelated universal decoder/reducer. Subprocesses use argv arrays. Git subprocess environments remove inherited `GIT_*` redirection and set `GIT_OPTIONAL_LOCKS=0` without modifying the parent environment. Preserve Unicode/terminal-column semantics and sanitize untrusted controls before styling. Avoid variadic expansion of unbounded rendered arrays.

## Identity, Context and Materials

- Resolve the project from each event's current cwd; cache keys include project/session identity. Pass explicit context keys to subprocesses/bash, never publish per-session identity into shared `process.env`. A valid caller pin intentionally shares identity; derived children still bind independent keys before failure can expose a parent pointer.
- Accept CLI task results only on successful exit, exact `session:<key>` provenance and no stale/error. Invalid pointers/records retain task_error, never authorize materials, hooks, journal paths or a no-task success. Child binding runs no start/hooks; clearing its pointer must not resurrect it from remembered dispatch headers.
- Task references are lexical descendants of `.trellis/tasks/` and realpath descendants of the resolved store. Only the explicit top-level source task-store route permits external material; target task stores, runtime/session stores and arbitrary references do not inherit that exception. Canonicalize existing ancestors without creating paths; dangling symlinks are not free destinations. Use bounded regular-file reads, UTF-8/NUL validation and explicit diagnostics; retain source/test-defined byte, traversal, expansion and diagnostic limits.
- Role JSONL explicitly selects references; it does not discover every spec or spawn roles. Every dispatch rereads material, including same-mtime changes. Deduplicate canonical files and bound directory expansion. Required artifacts and broken/empty references cannot silently become complete context.
- `assembleDispatchPrompt()` owns headers/delimiters and the complete-injection marker: strip caller-owned/quoted markers and sanitize loaded material. Add completeness only after complete valid loading. Byte prefixes or diagnostics require visible fallback, not guessed requirements. Material/header budgeting is not a hard cap on the entire prompt.
- Stable system sections contain stable workflow/overview only; volatile task state is a deduplicated message and role material remains in the dispatch prompt. Cache invalidation must follow root/session/role and task-changing events. Do not claim every cache is cleared or dispatch materials are cached permanently.

## Files, Publication and Resource Provenance

Installation registers the Pi package; explicit confirmed initialization/resource actions publish project resources. Startup never deploys roles, upgrades runtime, selects tasks or installs dependencies. Existing workflow/config/spec/history are user-owned. Safe updates preserve customizations and reject executable/role conflicts; explicitly confirmed manifest-less adoption and template replacement are distinct destructive actions, not safe updates.

The schema-2 project manifest separates exact executable resources from editable template provenance. Preserved-project fingerprints/revisions are diagnostics, not arbitrary read/write/recovery authorization. Initialization recovery reconstructs canonical package/skeleton outputs and verifies original ownership, not merely a planHash. Guard paths, source/output bytes and mode again under lock and before publication; publish the manifest last. Atomic replacement is per-file, not a multi-file transaction or OS sandbox. Failures preserve published files and history; inspect existing locks rather than deleting them as stale. Template replacement preserves its required backups.

`scripts/install.sh` stays Pi-only; historical patch/native-only deployment utilities are not full initialization or manifest bypasses. Bundled skills/templates/roles are package resources; project rules do not belong there. Preserve phase/state markers, role recursion guards, explicit direct-execution empty-manifest handling and independent implementation/review choice when those resources are intentionally changed.

Role adaptation belongs in `scripts/sync-agents.mjs:adaptAgent()`, with exact unique anchors and visible drift rejection. `resources/agent-baseline.json` records full source/adapted hashes for generated Claude roles from Trellis **0.6.17**; stamping that version does not authenticate arbitrary input. Authorized generation reviews fixed artifact integrity and the complete output set; writes are sequential, not transactional. Deployed custom roles are not bundled source and must not be overwritten for compatibility.

Keep original MIT integration/native code distinct from **AGPL-3.0-only** Trellis-derived runtime **0.6.16** and adapted roles **0.6.17**. Preserve attribution/modification notices, full original/output hashes and license metadata; the package is `(MIT AND AGPL-3.0-only)`, not wholly MIT/upstream-free. A source hash without the source is not independent integrity proof. See [user-facing provenance](../../../docs/runtime-baseline.md) and [role provenance](../../../docs/trellis-agent-sync.md).

## Worktree, Dispatch and Failure Preservation

- One native management owner implements preview/confirmed transitions; status and previews are no-write. Confirmation recomputes under the exclusive source lock, not from a persisted reservation. Default HEAD may change; bindings pin a full commit and canonical source/target/common-Git identity. Config changes affect new creates, not existing absolute bindings.
- Validate authoritative source records, Git registration/branch and local runtime paths; a target marker is only a hint. Reject overlapping/unsafe destinations, tracked/nonignored runtime paths and incompatible identity. Create/adopt never copies source code, installs, starts tasks or launches agents. Failure retains created directories/branches and error records.
- Preparation copies selected current-task artifacts/references only, not specs/code/config/source pointers. Non-task baseline references must match target bytes and have no uncommitted source difference. Target start uses the bound context and sanitized Git environment, including explicitly previewed hook risk. Hook edits remain target divergence; repeated ready preparation verifies rather than secretly refreshes.
- Python owns accepted-source graphs and per-file common ancestry. Refresh/collect use whole-file B/S/T decisions and prospective graph validation, not text merge/force. Preserve target-only divergence, edited source-deleted outputs and unselected source drift. Lifecycle metadata excluded from requirements stays target-owned; unknown requirement fields remain inputs. Recheck raw task metadata before writing to preserve concurrent lifecycle edits.
- Collect requires explicit eligible current-task files and dependencies; never propagate code/runtime/other tasks/credentials or target deletion. Missing/conflicting ancestry does not authorize overwrite. Source is the unique archive owner; collection is not Git integration or acceptance. Preserve source/target files, old descriptor and error state after partial multi-file publication; no automatic rollback. Retain bounded graph/snapshot limits and report sampled omissions honestly.
- Unbound tasks may use shared-source execution; different tasks may overlap but the same active/unknown task cannot. Bound tasks require existing prepared managed targets and never fall back to source or temporary isolation. Actual host cwd and persistent adapter/compatible role configuration are checked; a prompt cwd or parent-only `-e` is insufficient.
- Reserve starting before public spawn RPC, requery/recheck authoritative identity/readiness/fingerprints under lock, and render managed material from target. Return real provider IDs. Early terminal events reconcile with spawn replies; uncertain spawn/shutdown retains unknown. Stop requests cancellation but does not release occupancy before terminal evidence. Conditional source terminal publication rechecks request/state under the same lock and defers contention; exit is not a durable-flush guarantee.
- Ordinary Trellis Agent interception cannot cover third-party RPC/workflow launches; tools/roles/worktrees are not an OS sandbox. Invalid neighboring discovery can diagnose independently, but direct record reads remain strict. No automatic phase advancement, install, commit, merge or provider retry.
- Completed check snapshots are freshness evidence, not acceptance; both starting requirement revision and final checkout snapshot must remain current. Exclusions and large-file metadata fallback are not exhaustive change detection. Recovery requires proof of owner death, rechecks under lock and resets preparation, not arbitrary identity/material repair. Nonpositive/group PIDs, permission errors and unsupported probes cannot prove death.
- Removal refuses active/unknown execution, actual/supplied cwd, dirty targets and nonancestor integration references. Report ignored-file risks; ordinary Git remove only, no force/branch deletion. Clean only this binding's private regular snapshots after success. Preserve outputs through approved collection/integration first.

Evidence: `tests/{worktree,worktree-cli,preparation,material-sync,dispatch,source-executions}.test.mjs`, `tests/python/test_worktree.py`. Exact user commands belong in [worktree usage](../../../docs/worktree-execution.md), not another lifecycle spec.

## Task, Journal and Developer Safety

Fixed task/context/developer/journal code accepts only explicit valid keys, bounded valid task records and exact store paths; no sole-session/platform fallback. Deactivation clears only the calling pointer after successful unlink, runs hooks only for a valid task and does not finish/archive it. Bad/final symlink pointers must not authorize target reads or hooks. Archive rejects unsafe destinations before status/child/pointer changes. Journal/archive commit scopes are exact validated paths and preserve unrelated staged work; external stores are not mapped to a local same-name directory.

Developer names are safe nonempty single segments with source-defined limits; preserve legitimate Unicode/space names and historical journals. Reject dot/traversal/separators/control/format/surrogate names and symlink identity/workspace routes. Existing different identity is a conflict, not a silent switch. Preserve no-bytecode/no-global-Trellis behavior. Trusted hooks may run shell: validation is not a hook sandbox.

## Documentation Maintenance and Review

Specs are **English**, docs/ and task artifacts **Chinese**; README retains its language. Identifiers, commands, hashes and quoted upstream text are not translated. `docs/` is for users: feature behavior, commands, configuration, visible limitations and necessary provenance/license attribution. All development/testing methods belong in specs; historical designs/results belong in tasks. A small feature does not require a new spec file.

Classify before moving: retain effective reusable constraints, consolidate current user explanations and preserve archived evidence. Do not mechanically concatenate internal schemas/algorithms into a giant manual. Keep root navigation short; layer indexes contain real guidance; retain skill-required guides paths without repeated prose. Update current Markdown/JSONL paths and anchors, not archived assertions en masse. Never regenerate/install/deploy merely to repair a document link.

Review actual staged/unstaged/untracked and supplied-base committed changes, caller behavior and negative-case preservation. Self-review is not independent review. Keep approval, verified execution, check freshness, acceptance and lifecycle authorization distinct. Record exact final checks and limits under [testing guidelines](../testing/index.md).
