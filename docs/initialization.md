# 项目初始化

## 命令

```text
/trellis-init
```

安装包后即可使用，推荐用户级安装一次：`pi install --approve git:github.com/AkiChase/pi-trellis`；显式项目级安装加 `-l`，安装脚本使用 `--local`。项目不需要已有 `.trellis/` 或全局 Trellis CLI。普通项目启动无需 Python，真正初始化和运行时执行需要 Python 3.10+。

指令不接受参数，直接打开英文原生菜单；用户名在初始化或身份设置流程中选择。菜单包含 `Check project`、`Help`、`Cancel`，以及当前状态可用的初始化、接管、资源更新或模板操作。旧参数只返回迁移提示，不保留隐藏兼容。

打开菜单、查看帮助与取消不运行 Python。没有原生交互 UI 时仅返回使用指引；支持原生选择/确认的 RPC UI 仍可使用。只有最终原生确认才写入。`Check project` 只读，不安装或执行模型回合；选择后会生成一份有界诊断报告，检查 Trellis 在本项目的部署：项目发现、托管资源来源与完整性、初始化记录/锁、现存配置文件和本地开发者身份。不读取当前会话、任务或 worktree 状态。正常项汇总，异常给出位置、影响和处理建议，不输出正常资源长清单。检查先验证隔离 Python 环境；只有包来源与非空当前严格 manifest 通过，才运行本次捕获并校验的项目部署源码，验证共享配置、身份与 Pi Phase Index 消费者。旧版、缺失、损坏或中断的项目只运行独立环境探测，项目代码不执行。hooks 仅解析形态和数量，不执行或显示命令。检查有总时间、读取、输入与输出预算，失败、取消和未取得证明不会记为通过。在托管 worktree 目录中运行时只提示回源项目运行。宿主最终加载资源仍明确未验证；这不是完整材料扫描、准备/派发资格或 OS 沙箱。

## 项目激活与目标目录

未初始化或运行时旧版、损坏、中断时，本包只注册 `/trellis-init`；不注册 viewer 指令和 dispatch tool，不自动加载 Trellis skills、注入 workflow/task-state，也不显示任何[常驻任务栏](task-display.md)。运行时有效的 clone 即使缺本地身份仍启用完整能力。安装不是初始化，启动不会自动写项目资源或修复运行时。

从当前 `ctx.cwd` 向上逐级先检查 `.trellis`，再遇最近 `.git` 文件或目录停止；嵌套独立仓库不会继承外层项目。无 Git 时可继续找到文件系统根目录；异常标记不能被跳过后继承祖先。

`/trellis-init` 操作发现的 Trellis 根；不存在时使用最近 Git 根；两者都没有则使用当前目录。确认摘要显示绝对目标，取消不写入。因此从 `src` 启动不会把已有仓库再次初始化进子目录。

初始化、接管及资源修复成功后 reload 启用完整能力。运行中失效立即阻止相关执行并在后续事件清显示，完整撤回指令/tool/skills需 `/reload` 或新宿主；不清历史消息或用户 AGENTS。不支持一个 runner 内任意跨项目热切换。

Skills 动态来源仍在安装包，不复制到项目；用包 entry 的普通 `skills: []` 可关闭自动发现。`autoload:false` 的空数组是无操作 delta，`-path` 明确排除；`+path` 为加法，普通路径才是白名单。Pi `--no-skills` 仍允许扩展显式发现资源，用户显式静态路径也可能在普通项目出现；这些由宿主控制，不被插件撤回。动态资源显示来源与旧静态包列表不同。项目 trust/包覆盖规则保持 Pi 原语义。

## 新项目与已有 clone

新项目创建固定运行时、三个角色、可编辑 workflow/config/spec 入口、开发者身份、workspace 和 bootstrap 任务。不自动选择当前任务、运行 hooks、提交 Git 或安装依赖，也不自动扫描代码生成各层规范。

支持的 clone 缺少本地身份时，可选择历史名字或输入名字，只补缺失身份、workspace 与 onboarding 任务，保留历史。同名为无操作，不同已有身份会报冲突；支持合理 Unicode 和空格，危险路径名字会拒绝。

## 更新项目资源

已初始化项目提供 `Update resources`、`Check project`、`Help` 和 `Cancel`。选择 `Check project` 可查看托管资源缺失、修改或来源异常等静态诊断；检查不会自动修复，也不会把用户文档的正常定制当成文件 hash 故障。Skills 从安装包加载，不复制到项目。

安全更新可更新未修改的托管文件或恢复缺失文件；修改过的运行时或角色会阻止更新，不强制覆盖。定制的 workflow/spec 等文档保留，不重建身份、任务和日志。未知或不兼容项目需先明确处理。

确认更新后重新检查资源，成功刷新宿主并 reload。发布是逐文件进行的：中断保留已写文件，不承诺整项目回滚；重试时若资源已被其他操作修改，会报告冲突。遗留锁需检查，不自动删除。

## 接管无 manifest 的旧项目

已有 `.trellis/` 但无支持的托管 manifest 时，可选择 `Adopt project`。确认摘要显示安装、替换、创建、保留等分类数量与旧路径概况，并保留破坏性操作警告；大量路径以摘要展示，`Check project` 不作为完整写入清单的另一种查看模式。

**接管会无备份替换旧运行时、角色，以及 AGENTS/gitignore 的托管区域。** 区域外内容、已有 workflow/config/spec、身份、任务和日志保留；不会创建 onboarding 或删旧文件。重复或不完整标记、危险路径、不支持的运行环境会拒绝接管。

接管与安全更新不是同一动作。若接管中断，已写资源保留，需重新查看计划并确认；没有自动回滚。接管成功后仍缺身份的项目再单独设置身份。

## 采用包模板

健康源项目提供 `Apply template`，可选 Workflow、Spec 或两者。一次确认展示 Replace/Create/Same 路径，取消不写入；无逐文件选择、diff viewer 或自动合并。

这是**明确替换选中文档**，不是保留定制的安全更新：Workflow 选 `.trellis/workflow.md`，Spec 选包自带两个索引与两个 thinking-guide 文档。其他项目规范、配置、运行时、角色、身份和任务不变。

替换前会备份原文档和 manifest 到 `.trellis/.runtime/template-backups/<uuid>/` 并报告位置。失败保留备份和已写文件，不自动恢复。成功只刷新上下文，不部署运行时、启动任务、运行 hooks 或自动 reload。不支持远程模板。

## 使用边界

项目 `.trellis/.pi-trellis.json` 记录托管资源来源与版本，不应忽略或手工绕过。项目 workflow/config/spec/history 仍归用户所有；不要用上游 `trellis update` 替换固定脚本。

初始化必须在源项目而非 HOME 或托管 worktree 执行。危险 symlink、非普通文件、未知碰撞和定制托管标记会报错，不覆盖。文件级原子发布不等于全项目事务或 OS 沙箱。

运行时缺失、畸形、不完整或版本不匹配时不启用完整能力，相关执行被阻止，请打开 `/trellis-init` 并选择 `Check project` 查看。已有效激活项目中的坏任务指针仍报 task_error；不能把错误当作 No active task。普通读取/搜索不受影响，但 viewer 指令本身需要有效项目。宿主识别常见 Trellis 命令并非完整 shell 沙箱，外部独立进程仍需调用者负责。
